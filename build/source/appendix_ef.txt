## Appendix E, full text of two endpoints
@P This appendix holds the full text of two endpoints, EP02 and EP15, copied from docs/06_api_contracts.md. The other endpoints stay in that file. EP01, EP12 and EP27 are referenced by file name at the end of this section.
### EP02 POST /v1/trips (rider app; A1, B0, B1, B6)
@P **Who and ownership:** role `rider`. The trip's `rider_id` is `sub`. The quote must satisfy `fare_quote.id = body.fare_quote_id AND fare_quote.rider_id = sub`.
@P **Request:** headers `Authorization`, `Content-Type`, **`Idempotency-Key` (required)**. Body:
@TBL 8
Field | Type | Required | Limits
`fare_quote_id` | uuid | yes | a quote of this rider that has not expired and has not started a trip
`pickup_address` | string | yes | 1 to 300 characters, not blank
`dropoff_address` | string | yes | 1 to 300 characters, not blank
@END
@P **Flow (one transaction):** set the actor; insert the idempotency row; read the quote with the ownership condition; `INSERT INTO trip (id, rider_id, fare_quote_id, pickup_address, dropoff_address)` (status defaults to `requested`; the trigger writes the history row `(new) > requested`); `UPDATE idempotency_key SET response_status = 201, response_body = ..., trip_id = ...`. CONFIRMED in the walkthrough, `evidence/api_walkthrough_tests.txt`.
@P **Success:** 201, header `Location: /v1/trips/{id}`, body Trip (rider view, `status` = `requested`). A replay returns the same 201 body with `Idempotent-Replay: true`.
@P **Errors:**
@TBL 8
Status | Code | When | Database cause
409 | `rider_has_active_trip` | the rider already has a trip in requested, assigned, arrived or started | unique index `trip_one_active_per_rider`, "duplicate key value violates unique constraint "trip_one_active_per_rider"" (E01)
404 | `quote_not_found` | no quote with that id for this rider (unknown id, or another rider's quote) | ownership query; backstop FK `trip_quote_belongs_to_rider`, "insert or update on table "trip" violates foreign key constraint "trip_quote_belongs_to_rider"" (E02a, E02b)
409 | `quote_already_used` | the quote already started a trip | unique `trip_fare_quote_id_key` (E03)
422 | `quote_expired` | the quote's `expires_at` has passed | trigger `trip_enforce_transition`, SQLSTATE `RH004` (message "fare quote % has expired", E04); the API also checks `expires_at` first
400 | `invalid_idempotency_key` | header missing, empty, longer than 128, or has a space | backstop check `idem_key_length` (E32)
422 | `idempotency_key_reuse` | the key was used with a different body | none: the stored `request_hash` differs
409 | `request_in_progress` | the same key is still being processed | SQLSTATE 55P03 on the idempotency insert (concurrency test)
422 | `validation_failed` | an address is blank or too long, `fare_quote_id` is not a uuid, a field is unknown | none
@END
@P Also: 401, 403, 429, 500, 503 (common). **Order of checks:** replay and key checks come first, so a retry with the same key never returns `rider_has_active_trip` (it replays the 201). A new key after a success does return it.
@P **Idempotency:** keyed (section 1.7a), action `request_trip`. A retry cannot create a second trip: the stored answer is replayed, and even without it `trip_one_active_per_rider` and `trip_fare_quote_id_key` refuse a second trip.
@P **Session settings:** `rider`, `sub`.
### EP15 POST /v1/trips/{trip_id}/payments (rider app; A4, B3, B6, U1)
@P **Who and ownership:** role `rider`; `trip.rider_id = sub`.
@P **Request:** headers `Authorization`, `Content-Type`, **`Idempotency-Key` (required)**. Body: `payment_method_token` (string, 1 to 200 characters, an opaque token from the provider's own client library; the API never receives or stores card data). **The client sends no amount and no purpose.** The API reads the trip: status `completed` gives `purpose = fare` and `amount_minor = fare_amount_minor`; status `cancelled` with `cancellation_fee_minor > 0` gives `purpose = cancellation_fee` and that fee. Currency is `NGN`.
@P **Flow (three transactions, because a provider call must not hold a database lock):**
@P 1. Transaction 1: set the actor; `INSERT INTO idempotency_key ... ON CONFLICT DO NOTHING` (action `pay_trip`, `request_hash` includes the `trip_id`); commit. Replay rules of 1.7a apply here.
@P 2. Call the provider to start the charge, passing our `Idempotency-Key` as the provider's own idempotency key (assumption, decision 5). The provider returns a `provider_reference`. Provider unreachable or refusing: delete the key row, 502 `provider_error`, **no payment row exists**.
@P 3. Transaction 2: set the actor; `INSERT INTO payment (id, trip_id, purpose, amount_minor, currency, provider_reference)` (status `pending`); `UPDATE idempotency_key SET response_status = 202, response_body = ..., payment_id = ...`; commit.
@P If the process dies after step 2, a retry after 120 seconds repeats step 2 (the provider returns the same reference for the same key) and finishes step 3. If the client never retries, the provider's later webhook finds no payment with that reference and is stored as `needs_support` (EP19). This is a known gap.
@P **Provider capabilities used here (D5, DESIGN ASSUMPTION, owner may replace; full list in section 1.11).** Step 2 needs capability C1: create a payment with our idempotency key and get back a provider reference, with the same key giving the same reference and no second charge. Step 3 needs the reference to be unique (`payment_provider_reference_key`). The recovery after a crash (the retry after 120 seconds) needs C1 to behave that way. If a provider lacks C1, the retry is unsafe and the design must change: a payment attempt has to be recorded before the provider is called, which needs a migration, because `payment.provider_reference` is required today. Testing this endpoint needs C5, a sandbox.
@P **Success:** 202, header `Location: /v1/payments/{id}`, body `{"payment": Payment}` with `status = pending`. The result arrives later by the provider webhook (EP19); the rider polls EP16 or EP03 (`payments`).
@P **Errors:**
@TBL 8
Status | Code | When | Database cause
409 | `trip_not_payable` | the trip is not completed (and not cancelled with a fee) | trigger `payment_enforce_rules`, SQLSTATE `RH022` (message "a fare payment needs a completed trip (status is %)", E13)
409 | `nothing_to_pay` | the trip is cancelled with no fee | trigger SQLSTATE `RH024` (message "a cancellation fee payment needs a cancelled trip with a fee above 0", E14)
409 | `payment_already_exists` | a pending or succeeded payment already exists for this trip and purpose (made with another key) | unique index `payment_one_live_per_purpose` (E12)
502 | `provider_error` | the provider refused or did not answer; or it returned a reference already used by another payment | none for the first two; the second is unique `payment_provider_reference_key`
400 | `invalid_idempotency_key` | key missing or malformed | backstop `idem_key_length` (E32)
422 | `idempotency_key_reuse` | same key, different body or different `trip_id` | none
409 | `request_in_progress` | the same key is still running | key row without a stored response, or 55P03 (concurrency test)
422 | `validation_failed` | `payment_method_token` missing or too long, unknown field | none
@END
@P A wrong amount reaching the database (SQLSTATE `RH023`, "payment amount % does not equal the trip fare %", E15) is `internal_error`, because the API computes the amount. Also common.
@P **Idempotency:** keyed (1.7a), action `pay_trip`. A retry creates no second charge: the key row, the provider's idempotency key, and `payment_one_live_per_purpose` each refuse it.
@P **Session settings:** `rider`, `sub`.
@P File references: EP01 POST /v1/fare-quotes is in docs/06_api_contracts.md at line 289. EP12 POST /v1/trips/{trip_id}/complete is in the same file at line 458. EP27 GET /v1/trips/{trip_id}/events is in the same file at line 665.

### provider_event (source: 02_entities.md lines 278 to 294)
@P One row for each message the payment provider sends us (a payment or refund result). It is how a repeated or contradicting message is recognised (U4, A4, B6). Identifier: `id` (our uuid). The provider's own id, `provider_event_id`, is unique. Serves U4, A4, B5, B6.
@TBL 8
Field | Type | Req | Notes
id | uuid | required | primary key
provider_event_id | text | required | the provider's own id for this message; unique. A repeated message carries the same value
provider_reference | text | required | the provider's id of the payment or refund the message is about. Matches `payment.provider_reference` or `refund.provider_reference` by value. It is not a foreign key, because a message about an unknown reference must still be stored
event_type | text | required | payment_succeeded, payment_failed, payment_not_found (the provider answered a reconciliation check with "no record of this payment") or refund_succeeded
amount_minor | bigint | optional | kobo, more than 0; filled together with currency
currency | char(3) | optional | NGN; filled together with the amount
occurred_at | timestamptz | optional | the provider's own time of the event, as the provider states it. Not trusted for ordering, only kept for evidence
received_at | timestamptz | required | when we received the message. Default `clock_timestamp()`, not `now()`. Reason: `now()` is the start time of the transaction, so every event stored in one transaction would get the same value, and the rule P3 ("not older than the latest provider event of any type for that reference") could not tell which event came last. `clock_timestamp()` gives each row its own moment
processed_at | timestamptz | optional | when we finished handling it; filled together with outcome
outcome | text | optional | applied, ignored_duplicate or needs_support; filled together with processed_at
created_at | timestamptz | required | 
updated_at | timestamptz | required | changes once, when `processed_at` and `outcome` are filled
@END
